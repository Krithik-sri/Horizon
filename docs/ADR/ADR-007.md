# ADR-007: Native Android-first; the PWA is cancelled

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-07-31 |
| **Deciders** | Horizon team |
| **Supersedes** | [ADR-004](./ADR-004.md) |

## Context

Horizon pivoted from a friend-group bike-ride tracker to a premium native motorcycle companion
(`../PRODUCT.md`). That pivot removes the facts ADR-004 was decided on.

ADR-004 traded away background location for iteration speed: no dev-client build loop, distribution
by a shared URL, an afternoon from code change to a phone on a road. That trade was sound for a
bike ride where the phone is mounted and glanced at. It is not available to a motorcycle companion:
background GPS is table stakes, not a nice-to-have, and so is the Return register's durable ride
history — photos, journal, stats — which needs a real app shell and local storage, not a page that
ejects to a lobby on reload. The trade ADR-004 made no longer exists to take.

Worth stating plainly: this is a **reversion**, not a new direction. The original design already
specced React Native, and `mobile/` was scaffolded natively before ADR-004 bolted the PWA on top
of it. The PWA was the detour; native was always the plan.

## Decision

**The only client is the React Native / Expo app in `mobile/`. Android ships first, iOS later.
`web/` is deleted — there is no browser client, in v1 or afterward.**

## Alternatives Considered

**Keep both clients**, as ADR-004 intended. Rejected: a premium companion app is one experience,
not a lobby-link fallback that cannot do the two things the product now depends on.

**PWA + Capacitor wrapper**, revisited from ADR-004's own rejection of it. Still rejected for the
same reason — WebView `geolocation` under backgrounding is inconsistent — and now moot besides:
there is no PWA left to wrap.

## Consequences

- No more wake-lock workaround (`useWakeLock`, re-acquire on `visibilitychange`) — real background
  modes replace it outright, exactly as ADR-004's own migration path described.
- Dev-client builds are mandatory from day one, not deferred to Milestone 4: every native
  dependency (MapLibre, LiveKit) needs an EAS build before it can be tried.
- [`../SETUP.md`](../SETUP.md) replaces `docs/SETUP_WEB.md`, which is deleted along with `web/`.
- [ADR-003](./ADR-003.md)'s renderer table names `maplibre-gl` (the web renderer) as one of two
  targets. That row is now obsolete — noted here, not edited into ADR-003, per the append-only rule.

## Future Revisions

Revisit only if the product walks back toward a lightweight, install-free client — which would
itself contradict `../PRODUCT.md`'s "premium native companion" identity. Not a live possibility.
