# ADR-009: No standings, no ranking

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-07-31 |
| **Deciders** | Horizon team |
| **Supersedes** | — |

## Context

The pre-pivot product had a race-style "who's 1st/2nd/3rd" standings indicator: the server
projected each rider onto the route polyline and sorted by distance-along-route. `../PRODUCT.md`'s
"No Gamification" pillar explicitly bans badges, streaks, XP, levels, and **leaderboards** — and a
live ranking of riders, updated in real time and shown on-screen, is a leaderboard by any
definition, whatever it's named in the code. The Respect pillar reinforces this: nothing competes
with the road, and a standings position is exactly the kind of number that invites a rider to check
their phone instead of the corner ahead of them.

## Decision

**The standings feature is removed, not hidden.** `backend/internal/standings/` was deleted from
the repository, not left dormant behind a flag — dormant code with a live UI hook is a feature one
config change from returning. `riderState` in `backend/internal/hub/room.go` no longer carries `pos`
or `distAlong`, and the route-polyline projection math that computed them is gone with the package.

## Alternatives Considered

**Keep it behind a flag, off by default.** Rejected: a flag is a promise to keep the feature
working, and keeping a leaderboard *working* is precisely the thing the No Gamification pillar
rules out. Deleting the package is the honest version of "we don't do this."

**Keep distance-along-route computed but unranked** (e.g. for a future progress bar). Rejected for
now as scope the pivot doesn't need; see Future Revisions.

## Consequences

Riders in the `state` message are sorted by `id`, purely so the client list doesn't jitter between
frames as fixes arrive out of order. **This is not a ranking, and the UI must never present it as
one** — no position number, no "1st", no ordinal styling.

Convoy survives as a feature: seeing everyone on a map and talking via voice remains intact and is
named under "convoy experiences" in `../PRODUCT.md`'s long-term vision. It simply has no winner.

## Future Revisions

If a route-line feature later wants distance-along-route (e.g. an ahead/behind progress
indicator), it can come back — but only as presentation of one rider's own progress along the
planned route, never as a comparison or rank between riders. Anything that sorts or numbers riders
by position needs a new ADR, not a reinterpretation of this one.
